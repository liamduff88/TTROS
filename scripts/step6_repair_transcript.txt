ROOT CAUSE (established by direct inspection, not memory, per CLAUDE.md
"treat the instrument as the likeliest source of error"):

tools/aos_indexer.py `document_from_path()` runs a whole-document veto,
`SECRET_CONTENT_RE` (api_key|authorization|bearer|password|private_key|credential),
against the ENTIRE raw file text before any frontmatter parsing. If that regex
matches ANYWHERE in the file, the whole document is silently dropped from the
FTS index (returns None -> counted as "skipped", no error, no log visible to
an operator).

This whole-document veto is redundant with -- and strictly more destructive
than -- the line-level scrub the same function already performs on the
retained body: `sanitize_text()` (called immediately after) drops any
individual line matching `SENSITIVE_LINE_RE`, a strict superset of the same
keywords (api_key|secret|token|credential|password|authorization|bearer|
private_key|north_shore) plus more. That line-level scrub already prevents
any secret-bearing line from reaching the index. The whole-document veto adds
no additional protection over what line-level scrubbing already provides for
the retained body; it only produces false-positive total data loss when a
long-form conversational transcript happens to use one of these words in
ordinary English (asking about a website "password", a user's recording
"authorization") with no actual secret value nearby.
